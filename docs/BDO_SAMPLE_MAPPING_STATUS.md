# BDO 原始采样映射状态

数据来源：`midi_instrument_*.bnk` 的 Wwise HIRC MIDI Tracking 属性。

已从 HIRC 恢复并用于 GUI 试听的字段：

- 采样源 WEM/WAV。
- 根音（`MidiTrackingRootNote`）。
- 键位范围（`MidiKeyRangeMin/Max`）。
- 力度范围（`MidiVelocityRangeMin/Max`）。
- Event → ActionPlay → Layer/Random Container 奏法路由。
- Random/Sequence Container 的原始播放列表顺序、`AvoidRepeat`、全局/重置状态。
- Sound 父链上的实例组、实例上限、丢弃方向、全局范围与虚拟声部标志。
- 静态及区间 `Pitch` 属性。
- 父链静态 `Volume`/`MakeUpGain`、Volume Envelope 的 Note-Off Release。
- WEM `smpl` 循环区间、循环次数和 Note-Off 断环属性。

程序中的有效音块区间统一按下面的边界计算：

```text
有效键位 = 游戏内已验证编辑器音域 ∩ 当前 Wwise 音色库键位/力度分区
```

编辑器力度通道只在单选音符时显示当前乐器、音高、奏法与玛尔尼模式实际路由到的 Wwise 力度区切换点。该提示由选择器逐个检查 0–127 后确认样本组发生变化，属于资源映射结构证据；它不等同于游戏内实测响度、音色变化强度或最终混音听感。

Wwise 允许采样转调并不等于游戏编辑器允许写入，因此不会用宽泛的
`0–127` 采样区间覆盖已经验证的游戏音域。实时试听、离线渲染、转换检查
和音符编辑器共用 `src/bdo_music_composer/audio/bdo_instrument_samples.py` 的乐器/音色库路由；架子鼓也
只使用 `bdo_midi` 的一份 GM→BDO 映射，避免预览与导出选择不同音块。
采样选择顺序固定为“奏法 Event → 键位/力度音区 → 容器子采样”。有原生
奏法 Event 时不再叠加旧版的升八度、和弦堆叠或近似包络，避免泛音、和弦、
弱音等被处理两次。合成器 Event 也按游戏路由选择原生采样层，但滤波、LFO
和调制器仍使用近似试听，不会标记为 1:1。
容器在预览中采用确定性轮换，以复现 `AvoidRepeat=1` 且保证离线与实时结果一致。
游戏的随机初始子项、重放中断/reset 和 continuous 容器状态仍是确定性近似。

v145 HIRC 证据在 16 个旋律乐器库的 C4 边界包含 116 条不连续根音：同一区域
相对相邻采样额外降低 1–4 个八度。证据 JSON/TSV 保留原始值，实时试听与离线
渲染通过按“音色库 + 键区 + 原始根音”限定的校正表统一使用有效根音 60，避免
采样被额外加速 2–16 倍。长笛、笛子、打击乐及原生泛音路由不使用泛化修正。
`tools/audit_bdo_sample_mapping.py` 会核对 116 条已确认规则，并拒绝新的未登记
C4 低根音断层。

A/B 验证矩阵从 format 2 起不再用可能位于键区外的原始根音作为测试音高。
生成器会调用正式运行时选择器，按实际 Event、力度层和容器组划分连续键区，
并分别生成低端、中点、高端探针；矩阵保存映射证据哈希和不可变定义哈希。
旧版矩阵、证据版本不一致、删除待测探针、选中音源不一致，或任一探针尚未
通过时，GUI 和优化器均保持“近似/未验证”。只有同一乐器/奏法在所有音色库、
模式和键区探针全部通过后才会汇总为已验证。

2026-08-03 已从 PAZ meta v782 的 40 个 Wwise v145 MIDI Bank 重新生成映射。
新版仍为 3,579 条 Sound 路由、1,465 个唯一 WEM；Bank、Sound、Source、Event、
键域、力度层、循环、容器、实例限制、静态 Pitch/Volume/Release 与旧映射相比均为
零增删、零结构差异。每一行现在都记录根音来源节点和继承深度，且 3,579 行均无需
中点推断。另有 1,024 行检测到尚未建模的 Pitch RTPC 绑定；这些行会明确
`unmodeled_pitch_rtpc=true`，在 RTPC 尚未实现和完成游戏 A/B 前禁止进入已验证状态。
正式映射证据 SHA-256 为
`5f55d86377c9c23ee75c7fe5a736c7fb124e9fadb70e6da6c9fa0bf7a0eaa652`。
仓库只保留便携映射与哈希，不保存 PAZ、BNK、WEM、WAV 或本机路径。

同一份 v782/v145 映射的中性奏法审计显示，26 个有采样键位的逻辑乐器中有
10 个会随力度切换实际样本组：新手吉他 `126`，手鼓 `51/80/118`（最高音为
`80/118`），钹 `80`，弗洛凯斯特拉原声吉他与钢琴 `100/121`，架子鼓
`100/121`，竖琴 `121`，手碟 `60/100/121`，单簧管与圆号 `71/111`。
其余中性奏法没有检测到样本组切换；其他奏法仍按其 Event 路由逐音查询，不能
从此汇总表外推。边界 `126` 或 `121` 是资源中的真实分区，不应被 UI 擅自改成
通用的 `32/64/96` 动态标记。

当前 HIRC 还明确恢复了 8 个非零实例限制组（80 条音区行）：手鼓 4 组上限
1、钹上限 3、新手竖琴上限 5、架子鼓 2 组上限 1；全部为 per-game-object、
同优先级丢弃最旧且不使用虚拟声部。实时与离线路径先用同一个纯逻辑规划器
烘焙 4 ms 防点击释放和最终工程时长，播放及 Seek 不会再次执行。预览以
`track_id` 代理 Wwise game object；HIRC 无法证明游戏运行时对象恰好按编辑器
轨道划分，因此这个 scope 仍需游戏 A/B。

当前从 v145 银行按 Wwise FNV-1 事件名和 Event→ActionPlay 图自动恢复 102 个
GUI 奏法路由，其中 98 个覆盖
乐器完整编辑音域。三把电吉他的 `type 25` 是游戏限定的 C2–G2 FX 音区；圆号
`type 3` 的原生采样只覆盖 MIDI 24–72。超出这些奏法专属音区时不跨接到其他
奏法采样，避免把静音/无匹配误伪装成正确游戏音色。

## 已映射并使用 BDO WAV 试听

- 新手：吉他、长笛、笛子、手鼓、钹、竖琴、钢琴、小提琴。
- 弗洛凯斯特拉：原声吉他、长笛、架子鼓、低音提琴、竖琴、钢琴、小提琴、手碟、单簧管、圆号。
- 玛勒尼斯：玛尔尼贝斯，以及银色水波、高速路、赫克赛格莱姆三把电吉他。

这部分覆盖 GUI 的 22 种直接命名 BNK 乐器，并使用 BNK 中实际 WAV 样本渲染。
四种玛勒尼斯合成器的当前模式也已接入同一个离线/实时选区入口。

## 待人工确认

四种玛勒尼斯键盘乐器已接入实时试听的 synth 4×4 路由：

- 波纹行星（`0x14`）
- 幻象树（`0x18`）
- 秘密笔记（`0x1c`）
- 三明治（`0x20`）

每种乐器默认 `basic`，可选择 `stereo`、`super`、`superoct`；16 个格子均已找到解包 WAV。底层波形族对应关系仍是暂定路由，GUI 会标记为“原声近似 / 待游戏 A/B 验证”，不会标记为 1:1 已验证。

手鼓和钹的 Event 0/99 指向同一目标，架子鼓和手碟只暴露 Event 99，因此
试听会把这些打击乐的中性 `ntype=0` 临时路由到 Event 99，但不会改写正式
`Note`。手碟在正式游戏谱中使用 `ntype=0` 时的运行时调度仍缺少游戏录音
A/B 证据。

# 创作助手：从一个想法到可继续编辑的曲子

目标是协助创作者完成作品：空白时提供音乐草稿，已有旋律时提出伴奏，导入 MIDI 后
适配选定的游戏乐器，并让力度和音长更符合创作者选择的表达。每次建议都回到同一个
工程，能试听、选择、应用、撤销和继续手改。

## 产品路线

| 入口 | 创作者决定 | 助手负责 | 验收方式 |
|---|---|---|---|
| 从空白写起 | 调性、性格、长度和声部 | 提供不同动机、和声、低音和节奏草稿 | 能听、能逐音编辑、能导出 |
| 沿旋律编配 | 参考片段、调性、保留哪些原稿 | 根据可观察旋律给和声与伴奏候选 | 原旋律不变，停顿保留，新增声部可分别选择 |
| MIDI 游戏适配 | 目标轨和游戏乐器 | 检查已知音域、奏法与鼓组编码，提出明确改动 | 音符不丢失，未知约束不冒充已验证 |
| 演奏表达 | 片段、性格、是否重写已有力度/音长 | 节拍重音、乐句起伏、疏密和音长建议 | 保留手动奏法、保护范围外内容，比较试听 |
| 持续协作 | 接受、修改或放弃候选 | 记录用户主动提供的本地反馈，形成后续评价数据 | 不上传、不隐式训练，不把接受等同于质量标签 |

协作链路：**意图 → 明确范围与限制 → 多个候选 → 对照试听 → 选择声部 → 一次应用 →
继续编辑与撤销**。模型可替换，编辑器始终拥有最终音符。

## 本次实施范围

建立本机可运行的第一版：有明确控制的短曲生成、基于现有旋律的伴奏候选、游戏乐器
适配、片段表达重写、候选对照、撤销与可选本地反馈。先用可解释、确定性的音乐规则
把创作链路跑通；不将它标为已经学会玩家风格的通用模型。

内置草稿采用调内和声、声部连接、动机重复与变化；伴奏根据选定旋律的节拍和音高
证据选择和声。它们提供可继续创作的起点，质量需要人的判断。不会把第二轮的局部
缺音恢复成绩用作新编曲能力的评分。

第一版不接入云服务，不引入新训练依赖，不将玩家曲谱、模型研究目录或游戏音频
带进程序包。Marnian Muse 仍遵守独立引擎和 `.bdoopt` 扩展边界。

## 从规则走向学习模型

1. **作品表示与操作合同。** 固定创作意图、选区、保留条件、候选差异和失败诊断。
   同一合同供规则、检索与后续学习模型使用。所有候选必须通过编辑器与游戏校验。
2. **局部修复模型。** 将已完成的缺音/力度研究接到明确片段操作，先补足真实坏 MIDI、
   自然停顿负例、稀有乐器和不重复片段评价；模型与私有训练资料保持外部化。
3. **从主旋律到编配。** 以整轨删除构造训练任务，分别学习和声、低音、节奏与配器，
   和本次规则基线比较。跨曲谱组划分；未知曲目与库内参考分开报告。
4. **游戏演奏表达。** 力度、音长、奏法、乐器音域和混音分开建模。结构兼容与听感
   偏好分别评价。未经游戏实测的音色/奏法只能给建议。
5. **创作者偏好。** 用户选择和修改形成反馈；先在本机做候选排序和用户偏好实验。
   只有主动选择留存的真实修改对才可作为未来训练样本，撤销、试写与误操作不能自动
   当作正例。当前版本的反馈日志不包含曲谱音符或身份信息。
6. **自然语言协作。** 将“副歌更热闹、保留主旋律、别动前四小节”等请求解释成受限
   创作意图，先展示范围和变更，再调用同一候选接口。模型不能直接写工程或导出文件。

## 只有成品曲谱时，怎样建立学习任务

成品提供的是一种可观察的创作结果，没有“原始差谱 → 玩家修好”过程，也没有听感评分。
因此要分别建立修复、编配和表达任务，不能把每份成品都当成高质量标准答案。

| 任务 | 构造输入 | 学习目标 | 必须同时保留的反例 |
|---|---|---|---|
| 局部缺音 | 对成品副本删除少量音符或一小段声部 | 在明确补全范围内预测可能缺失的音符 | 原本的休止、切分、留白、非重复乐句 |
| 只有旋律 | 保留主旋律，遮住其他整轨；角色不确定时排除样本 | 和声、低音、节奏和配器候选 | 单声部本来就完整、不需要伴奏的作品 |
| MIDI 失真 | 分开注入力度平直、音长异常、八度错位、时间偏移和多余音符 | 按失真类型提出局部改动，保留未损坏内容 | 干净 MIDI、刻意的人性化节奏和手动奏法 |
| 游戏表达 | 按乐器与可确认奏法整理真实成品片段 | 学习相同节奏/乐句位置下的力度与音长分布 | 不同作者习惯、不同乐器模式和未知版本 |

所有遮盖和破坏都在数据划分后，对副本生成。同一曲目族、相同改编和近重复片段不能
跨越训练集与最终测试集。模拟损坏用于建立基线；真实导入问题和手点草稿另设评价集，
不能凭模拟恢复分数宣布已经解决真实低质量 MIDI。

模型选型从当前规则与重复片段检索开始：局部缺音先比较检索与小型掩码预测模型，
表达先比较简单统计模型与既有研究模型；只有前者的限制得到证实时才扩大到多轨
Transformer。长曲采用乐句/和声结构规划与局部音符生成两步，不靠一次性续写长串
音符承担全部曲式。模型输出仍是候选音符与明确操作，游戏约束在输出后独立复核。

## 协作怎样逐步变成可用的智能

第一版形成了固定入口、候选和可撤销的操作合同。当前本地选择记录只够研究“用户偏好
哪种性格或声部”，缺少输入和手改结果，不能据此训练音符修复模型。后续若建立创作者
主动保留的修改对，应包含当时的受限输入、可见候选、接受的部分和最终手改结果，并
区分试写、撤销与最终保留。曲谱内容继续留在私有数据区。

候选排序与音乐生成分别训练。先让排序器预测在给定创作目标下更可能被选中的方案，
再在独立任务上检查它是否真的减少手改、提高盲听偏好。记录候选展示顺序与未被选中的
候选，避免把“总排在第一个”误学为质量。用户接受一版只是一条偏好证据。

自然语言层最后接入：它可以选择动作、范围、保留条件和参数，不能绕过候选界面；
“补齐缺音”和“新写伴奏”属于不同创作意图，不能根据留白自行决定。当前尚未实现
自然语言入口、持续训练、玩家风格模型和长曲结构生成。

## 分阶段交付

| 阶段 | 交付物 | 进入下一阶段的证据 | 当前状态 |
|---|---|---|---|
| 创作闭环 | 四个入口、候选、试听、局部选择、撤销、工程/游戏导出 | 下文工程验证与六组可打开样本 | 本次已实现源码版 |
| 局部修复 | 独立扩展提供缺音与力度修复，沿用同一编辑操作边界 | 真实输入收益、干净输入误改率、与规则/检索对照 | 已有前期实验，产品接入待验证 |
| 学习编配 | 主旋律条件下的多轨候选与配器建议 | 未见曲目上的旋律保真、和声冲突率、盲听与手改成本 | 已定义任务与数据划分方案 |
| 游戏表达 | 按乐器的表达模型与效果证据 | 同一游戏版本、乐器和片段的实际演奏对照 | 尚待游戏录音与听感验收 |
| 协作学习 | 本地候选排序、可选择保留的修改对、受限自然语言意图 | 排序与生成分开评价，过期/越界/撤销行为通过 | 仅选择记录已实现 |

## 评价与晋升条件

- 工程安全：空白创建、导入、片段偏移、多轨、手动奏法、应用/撤销/恢复、MIDI 与
  BDO 往返均需通过；过期候选必须拒绝，音符增加必须是明确创作操作。
- 音乐质量：真实输入上盲比原稿、规则和模型，分开记录旋律保真、和声冲突、乐句
  连贯、配器可辨、表情与创作者偏好。试听次数或接受率不能单独证明质量提高。
- 模型评价：按曲目族划分训练/验证/测试，去重并标记已知改编；缺损、整轨编配与
  从空白创作分别建评价集。已反复使用的研究测试集不能继续作为独立最终测试。
- 游戏评价：在游戏内录制同一片段的原稿与候选，并记录具体乐器/奏法/版本。
  音符合法和本地近似试听通过，不等于游戏演奏效果已验证。
- 资源：默认本地轻量推断，计算有上限，后台处理，不在音频回调中加载模型或文件。
  大模型训练在小样本与规则基线有收益后再扩大。

## 状态与证据

源码工作区已实现第一版“创作助手”，从主工具栏进入。空白与伴奏操作每次提供最多
三个候选，按实际音乐操作去重，声部可分别选择；配器适配处理整条目标轨道，表达
调整限定到选定片段与小节。抒情伴奏分别提供整小节延音、半小节脉动和分解和弦，
同一和声也能比较不同织体；空参考等无改动结果只保留一份。
支持 2/4 至 6/4 拍，每次创作 1–16 小节，工程上限为 50,000 个音符。

已有人工奏法保留；默认只为力度平直的小节添加强弱变化。用户可以明确选择重塑已有
力度、调整音长。片段表达保留整轨音长倍率，避免改变兄弟片段的实际音长；跨片段
边界的裁切长音保持原样。GM 鼓编码必须明确指定，不能从
重叠的鼓键数字猜测。音域未知的乐器保持原音高，不能声称已经适配所有游戏约束。
配器适配作用于编辑音符；工程另有移调、乐器模式或效果设置时，仍由导出检查复核。

生成的声部使用新 TrackState，不继承参考轨的静音、Solo 或片段身份；同一种游戏
乐器沿用已有游戏音量与效果发送设置，因为 BDO 只保存一份该乐器的混音。配器适配
也遵循同一规则；目标乐器已有轨道的混音互相冲突时拒绝生成，并提示先统一混音。
候选在后台通过 API v1 校验并准备好结果后才可应用。界面选择声部时复用这些结果，
复制可变轨道容器、共享不可变 Note，避免重复分析整曲。修改参数会使候选失效；工程音符、片段、混音或
速度变化后，旧候选不能写回。应用进入一次项目撤销记录并触发原有自动保存。

“记录这次选择”默认关闭。启用后只在本机记录动作、性格、候选编号、选择声部与
接受/不合适反馈，最多 1,000 条；不包含音符、Owner ID、文件路径或曲谱摘要。
这些记录仅供后续评价，不会自动训练模型，也不能证明接受的版本更好。

可重复验证使用 `tools/verify_creation_assistant.py`，输出新的本地目录，包含六组
原创合成样本、可打开的工程、MIDI、当前通用试听引擎生成的 WAV、界面截图及 JSON
核验记录，并生成“开始这里.md”作为试听和打开工程的入口。两线程/两核限制在该
工具内落实；没有访问玩家资料或写入游戏目录。
六组样本已通过 MIDI 解析、工程恢复、BDO 字段往返以及真实 Qt 候选应用/撤销/恢复。
音频经过非静音、峰值和事件数量检查，尚未进行游戏内听感验收。

2026-09-16 源码验收：新增 18 项创作助手测试通过；完整回归运行 1,414 项，
1,402 项通过、12 项按既有条件跳过。语法检查、四语种 README 检查、仓库资源
检查与差异格式检查通过。可重复示例还覆盖了实际工具栏入口和对话框“应用”按钮。

早期语料及两轮实验保存在本地忽略目录，不作为应用运行时依赖，也不作为公开发行
素材。本次没有打包 EXE 或发布；现有发行版不会自动获得尚未打包的源码功能。
